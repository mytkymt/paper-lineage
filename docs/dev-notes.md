# dev-notes — paper-lineage

## 2026-07-30 縦ズーム不発の修正 / トレンド統合バー

- **Shift+ホイールの縦ズームが実機で無反応**だった。原因: macOS/Chrome は
  Shift+ホイールのスクロール量を **deltaY ではなく deltaX に付け替える**。
  ハンドラが deltaY しか見ておらず f=1 になっていた。合成イベントで deltaY を
  直接指定していたテストでは再現しない盲点(実機挙動の再現は deltaX で行うこと)。
  → 大きい方の軸 `|deltaY|>=|deltaX| ? deltaY : deltaX` を採用して解決。
- **トレンドリストを上流/下流の2リストから1本に統合**。行ごとに
  件数(12↑ teal / 567↓ orange)+ 2色の積み上げバー。バーの長さ = 合計(最大行比)、
  色の割合 = 上流:下流の比率。数字も併記(バーだけでは正確な比が読めないため)。
- クリックでカメラを動かさない方針は 2026-07-30 に確定済み(fitTo 削除)。

## 2026-07-30 系譜のローカル再クラスタリング + LLM 命名ボタン

「クリックした論文を基準に、通る論文たちで系譜を計算し直して命名したい」(要望)を
2段階で実装。毎回ではなく**系譜パネルのボタン押下時のみ**動く。

### Step 1: ローカルクラスタリング(API 不要・決定論)

- 選択論文の系譜(up ∪ down、高々数千ノード)の部分グラフを **Louvain** で
  クラスタリング。**ラベル伝播は失敗した**: 全メンバーが選択論文(ハブ)と繋がる
  密グラフでは1クラスタに潰れる(Tangible bits で 5,139→1)。
  - 対処1: **ハブのエッジを除外**(全員がハブ経由で繋がるため)
  - 対処2: LPA → **Louvain(モジュラリティ)**。パイプラインの帯レイアウトと同系。
- 決定論: 固定順序で local moving、利得タイは小 ID 優先。同一入力で同一出力を確認。
- 実測: Tangible bits(5,139ノード)66ms で 8 クラスタ
  (shape-change / tangible learning / sensing・textile / AR prototyping …)。
  VizWiz は crowdsourcing / accessibility / gig work に分離。妥当。
- 暫定ラベルはタイトルの TF-IDF 上位4語(idf は全38k タイトルから初回のみ構築)。
- 表示は上位8(カテゴリカル上限と同じ)+ 3本未満は捨て、**漏れた件数を必ず表示**。
- クラスタ行クリックで系譜をその集合に絞り込み(既存のサブ帯 drill-down と同じ
  paintLineage 経路。優先順: ローカルクラスタ > サブ帯)。

### Step 2: "Name clusters with AI" ボタン(任意)

- ビューアが実行時に LLM を呼ぶ**唯一の箇所**。claude-opus-5 に各クラスタの
  TF-IDF 語 + 被引用上位8タイトルを渡し、structured output(json_schema)で
  名前配列を受け取る。ブラウザ直叩き(`anthropic-dangerous-direct-browser-access`)。
- **「静的・決定論」の原則との折り合い**: 明示的なボタン押下時のみ + 結果を
  クラスタ内容(メンバー ID)のハッシュで localStorage にキャッシュ。
  同じ系譜なら2回目以降はネットワークを呼ばない。
- API キーはユーザー入力で localStorage 保存のみ(コードにもリポジトリにも置かない)。
  401 でキーを破棄して再入力へ。refusal / 形状不一致はステータス行に表示。

## 2026-07-29 citation intent の色分け(当初計画の最終項目)

S2 だけが返す citation intent(background / method / result)でエッジを塗るモードを追加。
「この引用は背景として引いたのか、手法を使ったのか、結果と比較したのか」が色になる。

### 構成

- `fetch_intents.py`(2b): 引用**する側**の論文ごとに S2 `/paper/{id}/references` を1回。
  コーパス内 DOI への参照だけを intent 付きで `data/graph/intents.jsonl` に保存。
  **paperId 単位のレジューム**で、いつ止めても続きから流せる。
- `intents.py`(6b): intents.jsonl → `data/viz/edge_intent.bin`(uint8 ビットマスク、
  **spc.tsv のエッジ順**)。bit3=取得済みマーカー(「未取得」と「取得したが S2 が
  分類していない」を区別する)。**spc.tsv が変わったら必ず 6b を再実行**(順序ずれ防止)。
- ビューア: Color に "Citation intent"。複数 intent は method > result > background の
  優先で1色に。分類済みは少数なので可視性増幅 ×4(量の表現ではない、ラボ線と同じ扱い)。
  凡例に**カバレッジを常時表示**。`edge_intent.bin` が無ければ選択肢自体を無効化
  ("no data" 表示 — 選べるのに何も変わらない、を避ける)。

### 実測(プローブ 30 論文)

- S2 の intent 文字列は `background` / `methodology` / `result`。対応表で method に正規化。
- **取得済みのコーパス内引用 269 本のうち intent が付いていたのは 27 本(約10%)**
  (background 24 / method 2 / result 1)。S2 は本文の citation context が読める論文しか
  分類できず、ACM 論文は大半がその対象外のため。→ フル取得しても色が付くのは
  1割前後と予想。**「分類なし」を沈めて描く前提の設計にした理由。**
- レート制限: 無認証 4秒/req で全 38,791 論文 ≈ 43時間、`S2_API_KEY` で ≈ 11時間。
  少しずつ流して凡例のカバレッジが育つ運用。

## 2026-07-29(同日)帯ラベルの LLM 命名(F3)

暫定表示(年・件数・TF-IDF キーワード)を置き換え、14帯 + 117サブ帯すべてに英語名を付けた。

### 設計判断

- **命名結果は `viewer/band-names.json` としてコミット**する。実行時に LLM を呼ばず、
  静的配信・決定論(同じ入力 ⇒ 同じ表示)を守る。パイプラインにも API 依存を増やさない。
  命名自体は Claude セッション内で keywords + top_papers を読んで生成した(= 生成器は
  対話セッション。レイアウト再生成後は meta.json の帯情報を再プロンプトして作り直す)。
- **鮮度チェック**: 各エントリに `sig`(TF-IDF キーワード先頭3語を `|` 連結)を持たせ、
  ビューアは sig が一致した帯にだけ名前を適用する。レイアウト再生成でコミュニティが
  入れ替わった場合、**古い名前を黙って出さずキーワード表示に落ち**、console.warn で
  stale 件数を出す(サイレント陳腐化の禁止)。
- ラベル書式: `名前 · 年レンジ · N papers`。キーワードは捨てずに **title 属性
  (ツールチップ)へ退避**。系譜パネルのトレンド行もサブ帯名を使う(同じくツールチップに
  キーワード)。孤立帯(community null)は命名対象外で従来の注記のまま。
- 検証: sig 照合スクリプトで不一致 0 を確認してからコミット。`main.js?v=7` に更新。

## 2026-07-29(同日)人で検索して色を固定 / 右パネル拡充 / 関連語検索

### 色を付ける対象を「固定の上位8ラボ」から「検索して選んだ人」へ

上位8ラボ固定は「自己引用リンクが多い順」という**誰も聞いていない問い**に答えていた。
人を検索して色を固定できるようにし、色を**ユーザーが制御するチャンネル**にした。
8色制限はデータの制約ではなく「同時に比較できる人数」の制約になる。

- パイプラインは色スロットではなく**ラボ ID**(= ラストオーサーのインデックス)を書き出す
  → どのラボに色を付けるかはビューア側で自由に変えられる
- 著者名テーブル(59,964人)を meta に持たせ、ノードは名前ではなく**インデックス**を持つ
  (名前を直接持つと meta.json が数MB膨らむため)
- 既定は自己引用系譜が長い順に上位8人。検索で入れ替え可能

**当て方(人の範囲)は点と線で同じ定義**を使う。線はその条件を**エッジの両端**に課したもの:

| 人の範囲 | 点 | 線 |
|---|---|---|
| 著者に含まれる(共著も) | その人が著者の論文 | **両端の論文にその人が入っている引用** = その人自身が繋いだ流れ |
| ラストオーサーのみ | その人がラストオーサーの論文 | 両端のラストオーサーが一致 = ラボの系譜(前計算と一致) |

当初は線をラストオーサー固定にしていたが、点だけ切替可能なのは非対称なので揃えた。
`any` は共著で入った引用も拾うので**帯を越えて広がり**、`last` は自分の帯に収束する。
この差自体が「その人個人の広がり」と「ラボとしての系譜」の違いを見せる。

実装: 固定した人ごとに 1 ビットを立てたノードマスク(最大8人なので Uint8)を作り、
エッジは `mask[u] & mask[v]` で判定する。エッジ 371,893 本の 1 パスで済むので、
切替のたびに再計算しても体感できる遅延はない。

「色を付けたのに線が出ない」= その人にラボ系譜がない、というケースがあるので、
検索結果に「自己引用系譜 N」または「系譜線なし」を出している。
なお**固定していない人のラボ線は前計算(ラストオーサー基準)のまま**「その他のラボ」に
落ちるので、そこだけは人の範囲の切替が効かない。

注意: OpenAlex の著者 ID は**同一人物が複数 ID に分裂することがある**
(実測: "Hiroshi Ishii" が 96本/系譜195 と 22本/系譜1 の2エントリに分かれている)。
分裂した側は別人として扱われるので、系譜が過小評価される。

### 右パネルに著者を表示

著者を並べ、**最後の1人(ラストオーサー)に ◂ を付ける**。クリックでその人の色を固定できる。
固定済みの著者はその色で表示される。

### トレンド行のクリックで系譜内を絞り込み

系譜パネルのトレンド行をクリックすると、**その系譜のうちそのサブ分野の論文だけ**が残る。
再クリックで系譜全体に戻る。前計算済みのサブ帯を使うので計算は走らない。

**初版に2つバグがあった(どちらも同じ原因)**:

1. 上流リストの行を押すと上流だけ、下流の行を押すと下流だけしか残らなかった。
   → 押した行の向きに関係なく、**前後どちらもそのサブ分野で絞る**のが正しい。
2. 1つ押したあとに別のトレンドを押すと**何も残らなかった**(実質 AND)。

原因はどちらも `highlightTrend` が `nodeState` を**破壊的に**絞り込んでいたこと。
2回目のクリックは「1回目で絞った結果」をさらに絞るので、別のサブ分野なら必ず空になる。

→ 選択時の系譜(`{i, up:Set, down:Set}`)を保持し、絞り込みのたびに
**そこから毎回描き直す** `paintLineage(subFilter)` に変更。状態を積み上げずに
常に「選択 + フィルタ」から再構成する形にした。

## 2026-07-29(同日)ラボごとの色分け / 系譜が空になる理由

### 色分けを「3段階の帰属」から「ラボごと」へ

独立/著者重複/同一ラボの3段階ではなく、**ラボ(= ラストオーサー)ごとに色を変える**方式に変更。
ラボの定義は前節の level 2(引用元と引用先のラストオーサーが一致)のまま。

- level 2 エッジをラストオーサーで集約 → **2,121 ラボ**
- 上位8ラボに色スロット、9位以下は「その他のラボ」(16,188 エッジ)に畳む
- 上位8: Florian Mueller 252 / Hiroshi Ishii 195 / Enrico Rukzio 172 / Patrick Baudisch 164 /
  Hans Gellersen 159 / Pamela Wiśniewski 159 / Yuanchun Shi 156 / Jürgen Steimle 156
  → HCI の顔ぶれとして妥当。**各ラボが自分のサブ分野の帯の中で水平な線として出る**
  (Ishii がタンジブル帯を 1997→2022 で貫く、など)

配色は dataviz リファレンスパレットの dark ステップをその順序のまま使用。
**カテゴリカルは 8 が上限**(9個目に色相を作らず「その他」に畳むのは非交渉ルール)。
validator 実測: 隣接ペア基準は全項目 PASS(最悪 CVD ΔE 8.4)。
all-pairs 基準では FAIL(最悪 1.6)だが、**ラボの線は帯ごとに空間的に離れて出る**ので
隣接ペア基準を採る。ただし CVD ΔE 6–8 の帯域は二次符号化が必須なので、
**凡例クリックで1ラボに絞り込める**ようにした(色だけに identity を負わせない)。

### 系譜が空になるのはコーパス境界のせい

「論文を選んでも引用論文が全然出ない」ことがある件。データ欠損ではなく**設計どおり**:

系譜は **コーパス内(HCI 13会議)に閉じた引用 DAG** の上でしか辿れない。
参照 1,499,177 本のうち **1,125,440 本(75%)はコーパス外**で落としている。

| | 本数 | 割合 |
|---|---:|---:|
| コーパス内の参照が 0 本(遡る系譜が空) | 6,248 | 16% |
| コーパス内の被引用が 0 本(その後が空) | 9,450 | 24% |
| 両方 0(完全に孤立) | 3,685 | 9% |

年別に見ると 1990年は47%、2010年は23%、2024年は4% が「遡る系譜が空」。
古い論文ほど、当時 HCI 会議の外(認知科学・心理学・書籍)を引いていたため空になりやすい。
2026年が 24% と高いのは、まだ被引用が付いていない/参照先の紐付けが未完了なため。

例: **Tangible bits (1997)** は参照22本中コーパス内が3本しかない。被引用は 5,124 本ある。

→ 対処として、系譜パネルに **「参照 N 本中 M 本がこのコーパス内」** を常時表示するようにした。
0 本のときは「HCI 13会議の外を引用しているため遡れません」と明示する。
**沈黙して空リストを出すと「データが壊れている」と誤読される**ため。

将来的にコーパス外への参照も辿りたい場合は、OpenAlex から 1 ホップ分の外部論文を
取り込む(コーパスを閉じない)必要があるが、ノード数が数十万に増えるので別途検討。

## 2026-07-29(同日)色分けを「帰属」に決定 + 系譜操作の絞り込み

### 色分けの方針: B(帰属)を採用

3案を比較した結果:

| 案 | 色が意味するもの | 判断 |
|---|---|---|
| A. 帯(サブ分野) | どのトレンドに属するか | **不採用** — 位置(帯レイアウト)と冗長 |
| B. 帰属 | 誰がその線を作ったか | **採用** |
| C. venue | どの会議か | 補助モードとして残す |

理由: 時間軸 + 帯レイアウトで「いつ・どのトレンドか」は既に**位置**が表している。
色は位置が表現していない情報に使うべきで、当初からの問い「この太い線は
1ラボの系譜か分野トレンドか」がまさにそれ。

### 「著者が1人でも重なれば同じラボ」は粗すぎる → 3段階にした

指摘を受けて、二値ではなく段階を分けた:

| level | 判定 | 割合(371,893 エッジ中) |
|---|---|---:|
| 0 独立 | 著者の重なりなし | 85.8% |
| 1 著者重複 | 著者は重なるが**ラストオーサーは別** | 9.5% |
| 2 同一ラボ | **ラストオーサーが同じ** | 4.7% |

level 1 は「指導教員が変わった」「共同研究」「大著者リストの偶然の重なり」を含むので、
**「1ラボの系譜」として扱うのは level 2 だけ**。HCI は last author = PI の慣行が強いので、
ラストオーサー一致がラボ同定に一番近い。

注意: この判定は OpenAlex の author ID に依存する。同一人物が複数 ID に分かれていると
level 2 を取りこぼす(過小評価側に倒れる)。著者情報が無いノードに接するエッジも
判定不能として level 0 に倒しており、**自己引用を過大評価しない方向に統一**している。

- 描画: 同一ラボは全体の 4.7% しかなく等 alpha だと独立エッジの海に埋もれるため、
  level 1 は ×2.0、level 2 は ×3.5 の alpha 増幅を入れている。
  **これは可視性のための増幅であって量の表現ではない**(コードにも明記)。
- 「ラボ線のみ」チェックで level ≥1 のエッジだけを描ける。自己引用の骨格だけが残る。

### 系譜表示中の操作を系譜内に絞った

沈めて表示しているノードにホバー/クリックが吸われ、系譜を読んでいる最中に
関係のない論文へ飛んでしまっていた。`pick()` に「選択中は `nodeState != 0` のみ」を
入れて解決。**副作用として、系譜外をクリックすると「ヒットなし」→ 選択解除 →
全体ビューに復帰**になり、要望の2点が同じ1箇所の修正で揃った。

## 2026-07-29(同日)密度問題を解決 — 帯が見えるようになった

「後半の密度が高すぎて何も見えない」への対処。**2段階の別問題**だったことが分かった。

### 問題1: 加算合成の飽和(描画レイヤ)

0–1 のフレームバッファに直接足していたので、重なりが 20 本程度で白飛びし、
1980年代(重なり数本)と2020年代(重なり数百本)を同じ線形スケールで見ていた。

→ **RGBA16F の HDR バッファに蓄積し、対数圧縮でトーンマッピング**する2パス構成に変更。
`log(1 + exposure*v) / log(1 + exposure)` + ガンマ。**データは一切間引いていない。**
float テクスチャが使えない環境では従来の直接描画にフォールバックする。

これで白飛びは消えたが、**まだ均一な靄のままだった。** → 問題2。

### 問題2: レイアウトが流れを帯にまとめていない(本質)

幹だけ(SPC 上位25%)を描いて診断したところ、**線が上下にジグザグしていた**。原因は
barycenter の後に**年ごとに順位で [0,1] へ再正規化**していたこと。まとまった集団でも
その年の論文数に応じて画面いっぱいに引き伸ばされ、同じ流れが年をまたいで同じ帯に留まらない。

試した順:

1. **スペクトル埋め込み(Fiedler ベクトル)** — 失敗。1本の軸は本質的に1回の分割しか
   表現できず、数十あるトピック集団を分離できない。全体順位変換も結局集団を引き伸ばす。
2. **コミュニティ帯(採用)** — Louvain でコミュニティを取り、
   コミュニティ間引用量のスペクトル順で並べ、**論文数に比例した幅の帯**を割り当てる。
   帯の中はコミュニティ内スペクトル順。→ **横方向の帯がはっきり出た。**

58 コミュニティ → 400本未満を「その他」に統合して 14 帯。所要 6 秒。

得られた帯(上から):

| 本数 | 代表論文 |
|---:|---|
| 4534 | KinectFusion / User-defined gestures / FTIR multi-touch |
| 1469 | ART nonparametric / 触覚 / VR |
| 3373 | Tangible bits / Technology affordances |
| 3023 | user satisfaction 尺度 / ubicomp charting |
| 2495 | UX / context-aware guide / Alone together |
| 2751 | VizWiz(アクセシビリティ) |
| 4304 | Social information filtering / AI Literacy / Distributed cognition |
| 1271 | GPS mobility / Email overload |
| 1676 | Heuristic evaluation / Computers are social actors |
| 974 | Awareness in shared workspaces / MTurk / GitHub |
| 2178 | StudentLife / activity sensing / personal informatics |
| 4052 | Research through Design |
| 2903 | Bowling alone / microblogging |
| 3685 | (コーパス内に引用リンクなし) |

**HCI のサブ分野として読める。** 隣り合う帯が関係の近い分野になっている点も期待どおり。

### 副次的なバグ

小さいコミュニティ約45個が極細帯として密集し、境界線(`#ffffff10`)が重なって
**白い横線1本に見えていた**。→ `--min-community`(既定400)未満は「その他」帯に統合。

### 追加した機能

- **タイトル検索**: 全語 AND のサブストリング一致。ヒットを黄色で強調し、他を沈める。
  38k 件の線形走査で十分速い(120ms デバウンス)。
  例: "fabrication" 131件 → Tangible bits 帯の2015年以降に集中しているのが一目で分かる。
- **帯ラベル**: 各帯の右端に「年レンジ・本数・代表論文」。**LLM 命名(F3)で置き換える前提の暫定表示。**

### 検証: SPC の main path が読めるか(最初のゲート)

**通った。** グローバル main path 63 本が44年分の一本の系譜として読める:

自分の知っている HCI の流れと一致する。**レイアウトを作り込む価値がある、と判断してよい。**

### 検証: 帰属分析(ラボの系譜 vs 分野トレンド)

SPC 上位 0.5%(1,859 エッジ)の弱連結成分:

| 本数 | 年 | self-citation | 独立グループ | 解釈 |
|---:|---|---:|---:|---|
| 962 | 1981-2026 | 0.28 | 169 | 分野トレンド(Tangible bits 等) |
| 10 | 2020-2024 | **0.89** | **2** | **ほぼ1ラボの自己参照ライン** |
| 5 | 2009-2012 | 0.40 | 3 | 中間 |

**狙った判別が実際に効いている。** 指標だけで (a) と (b) が分離できた。

ただし **962 本の巨大バンドルは弱連結成分が粗すぎる**。幹ネットワークは高度に連結しているので、
成分分割ではほぼ1個になる。→ 幹の中でコミュニティ検出(Leiden 等)が要る。**次の課題。**

### ビューア

- WebGL2 で 38,791 点 / 371,893 線を一度に描画。動作は軽い。
- **論文をクリックすると系譜ビュー**: 上流(teal)= 遡る系譜、下流(orange)= その後の系譜。
  深さ既定 2 ホップ(無制限だと数千本になって塊にしか見えない)。選択時に系譜の範囲へ自動フィット。
- ハマったバグ2つ(どちらも座標系):
  1. **canvas は置換要素**なので `position:fixed; inset:0` では viewport に伸びず、
     `canvas.width = clientWidth * dpr` の結果が CSS サイズにフィードバックして毎フレーム膨張していた。
     → CSS で `width:100vw; height:100vh` を明示。
  2. シェーダは data y=0 を画面下に置いていたのに、マウス処理は `clientY`(下向き正)をそのまま使っていた。
     → **縦のパン・ズーム・ホバーが全部反転。** シェーダ側で y を反転し、
     正規化座標を「左上原点・画面と同じ向き」に統一。逆変換は `screenToNorm()` 1箇所に閉じ込めた。

### まだ出来ていないこと

- **全体ビューで「太い流れ」が帯として見えていない。** 加算合成の alpha が、
  疎な年(1980年代)と密な年(2020年代)で桁違いに効くため、低いと何も見えず高いと飽和する。
  → 密度で正規化するか、SPC 上位だけを別レイヤで太く描くか。**次の主要課題。**
- 幹の中のコミュニティ検出(上記)
- LLM によるバンドル命名(F3)
- citation intent による色分け

## 2026-07-29(同日)スコープ改訂 — ego-network から分野スケールへ

既存ツールへの不満が具体化したので方針を変えた。

- 既存ツールは **表示数が少なく、映っているものが意味のある流れか判断できない**。また **配置がネットワーク的で時代の流れが読めない**。
- 見たいのは個々の論文ではなく **全体のトレンド感**。→ **表示数が多くなることは許容する。間引きは思想ではなく性能上の妥協に降格。**
- 全部描いたときに現れる **互いに引用し合う太いライン** が本命。それが「ラストオーサーの研究ビジョンで引かれた線」なのか「実際にできたトレンド」なのかまで見たい。
- **全文 LLM 解析は不採用**(しんどい・見合わない)。色分けは citation intent API のみ。**LLM は抽出したバンドルに名前を付ける役だけ**に限定。

→ `scope.md` を全面改訂、`algorithms.md` を新規作成。

### 調査で分かった重要なこと

- **Main Path Analysis**(Hummon & Doreian 1989 / SPC by Batagelj 2003)が、まさに「引用 DAG の中の太い線」を取り出す確立手法だった。**自前で発明する必要はない。** DAG なら前向き・後ろ向き2パスの DP で線形時間。
- **semantic main path network analysis**(2023)という、citation context と main path を組み合わせた先行研究がある。F3 の狙いに近いので**要精読**。
- OpenAlex は snapshot(約330GB圧縮 / 1.6TB 展開)と、フィルタ付きサブセットを落とす **公式 CLI** がある。HCI 会議に絞れば手元で扱える規模のはず。
- → 手法は既出。差分は **(1) 分野スケール + インタラクション**、**(2) 太さの帰属分析(1ラボの系譜 vs 分野トレンド)**。特に (2) は先行が見つかっていない。

### 次にやること(優先順・改訂)

1. **OpenAlex CLI で HCI 会議(CHI / UIST / CSCW / DIS / TOCHI / IUI / UbiComp)の works を落とす。** 実際のノード数・エッジ数を数える。ここでスケール感が確定しないと以降の設計判断ができない。
2. **サイクル除去 + SPC 計算**をオフラインスクリプトで実装。可視化なし、数値だけ。SPC 上位エッジの論文を見て、**自分の知っている「流れ」と一致するか**を確認する。ここが最初の検証点。**一致しないならレイアウトを作っても無駄。**
3. **cross axis のベースライン(候補 D: ランダム / ID 順)で全ノードを WebGL 描画。** これで既に流れが見えるかを確認。
4. 見えなければ候補 B(埋め込み1次元射影)→ 候補 C(ハイブリッド)へ。→ `algorithms.md`
5. バンドルの著者重複率 / 独立グループ数を計算し、太い線の帰属を出す。
6. バンドルに LLM で命名。
7. citation intent は最後。lazy 取得で足りるか判断する。

> Litmaps / Research Rabbit を触る件は、ユーザーが既存ツールへの不満を具体的に述べたため優先度を下げた(ただし CitNetExplorer の**レイアウト**は候補 A の参考として見る価値がある)。

### 決めていないこと

- プロジェクト名。`paper-lineage` は仮。
- 時間軸の向き(縦 / 横)。→ 3 で両方試す。
- コーパスの境界。会議で閉じると外部分野からの流入が切れる。topic ベース or seed から到達可能な範囲、という選択肢もある。
- 公開するか。オフライン前計算 + 静的配信なら公開は容易(レイアウトを決定的にする方針と整合)。
