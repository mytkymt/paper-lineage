# アルゴリズム設計メモ

大規模(10^4〜10^5 ノード)の引用 DAG を、時間単調に配置し、太い流れを取り出すための設計候補。

## 1. Cross axis(時間と直交する軸)の決め方

時間軸は固定なので、**自由度はもう一方の軸しかない**。ここの選び方で「流れが見えるか / ただの散布図か」が決まる。

### 候補 A: Sugiyama 型の層別交差最小化

- 年 = 層(layer)とみなし、層内の順序を barycenter / median heuristic で反復的に決める(隣接層の接続先の平均位置に寄せる)。
- **長所**: エッジ交差が減り、引用の連鎖が視覚的に連続した帯になる。まさに「太いライン」を見せるための古典手法。
- **短所**: 軸に意味がない(「上のほう」に置かれた理由を説明できない)。ノード数が多いと反復コストが効く。層内が数千ノードだと1層のソートも重い。
- 実装難度: 中。既存実装は数千ノード想定のものが多く、10^5 では自前で書く必要がありそう。

### 候補 B: 埋め込みの1次元射影(意味軸)

- SPECTER2 / OpenAlex topic embedding で各論文をベクトル化 → UMAP や PCA で **1次元**に落とす。
- **長所**: 軸に意味がある(「近い位置 = 似たトピック」)。同じトピックが年をまたいで**同じ帯**に留まるので、時間方向の流れが自然に横縞として現れる。決定的にしやすい。
- **短所**: 1次元は情報を捨てすぎる可能性。トピックの分岐(1つの帯が2つに割れる)を1次元で表現できない。
- 実装難度: 中。埋め込みの入手が前提(S2 API か OpenAlex topics)。

### 候補 C: ハイブリッド(有力)

1. 埋め込みで**粗い帯(バンド)**を決める(クラスタ単位で cross axis 上の区間を割り当て)。
2. **バンド内**でのみ Sugiyama 的な交差最小化をかける。
3. バンドの並び順自体も、バンド間の引用量が多いものが隣接するように決める。

軸の意味を保ちつつ、局所的には流れが繋がって見える。**まずこれを狙う。**

### 候補 D: 何もしない(ベースライン)

- cross axis をランダム or ID 順。**必ず最初に描いて比較対象にする。** これで既に流れが見えるなら A/B/C の作り込みは不要かもしれない。

> 実装順: **D → B → C**。A は C の部品として必要になったら書く。

## 2. 太いラインの抽出

### Main Path Analysis(採用)

Hummon & Doreian (1989) 提案、Batagelj (2003) が SPC を追加。引用ネットワーク(DAG)における「知識の流れの幹」を取り出す確立手法。

- **SPC (Search Path Count)**: 全 source(古い端)から全 sink(新しい端)への全パスを走ったとき、そのエッジが何回通過されるか。
- 計算: DAG なので動的計画法で線形時間。
  - 前向き: `f(v)` = source から v に至るパス数
  - 後ろ向き: `b(v)` = v から sink に至るパス数
  - エッジ `(u→v)` の SPC = `f(u) * b(v)`
  - 数値が爆発するので **log 空間 or 多倍長 or 正規化**で持つ(10^5 ノードだと普通に overflow する)。
- 他に SPLC / SPNP / NPPC があるが、まず SPC でよい。

**単一 main path ではなく、SPC 上位 p% のエッジからなる部分グラフを描く。** 分野の流れは1本ではないので、「幹ネットワーク」として複数の並走トラジェクトリを見せる。

### 前処理: サイクルの除去

理論上引用は DAG だが、実データには**サイクルが混入する**(同年の相互引用、preprint と本刊の年不整合、データエラー)。SPC は DAG 前提なので、

- 年で厳密にソートし、同年内・逆行のエッジを別扱いにする、または
- 強連結成分を潰す(cyclic citation network 向けの main path analysis の変種も提案されている)。

**この前処理を雑にやると全部壊れる**ので、最初に作る。

### コミュニティ検出

命名(F3)と色分けのために、無向化した引用グラフに Leiden をかける。main path とは別軸の分割なので、両方持っておく。

## 3. 「誰が作った太さか」の判別

各バンドル / main path について:

- **著者重複率**: 構成エッジの引用元・引用先で著者集合が交差する割合。自己引用エッジの比率。
- **独立グループ数**: 著者を共著ネットワークで連結成分に分け、そのバンドルに何グループ乗っているか。
- **ラストオーサー集中度**: last author の分布のエントロピー(HCI ではラストオーサー = PI 慣行が強いので効くはず)。

→ 「1ラボの系譜」と「分野トレンド」を連続値で区別し、色 or 記号で示す。**消さずに区別する**(ラボの系譜も見たい情報)。

## 4. LLM の使いどころ(限定)

- 入力は**バンドル単位**(数十〜数百件)。1バンドルにつき代表論文10〜20本のタイトル・会場・年レンジ。
- 出力は短い名前 + 1行説明。構造化出力で受ける。
- **全文は渡さない。abstract すら必須ではない。**
- ズームレベルごとにラベル粒度を変えるなら、階層クラスタの各レベルで同じことをすればよい。

コストは論文数ではなくバンドル数に比例するので、コーパスが10万本でも問題にならない。

## 5. citation intent(F3 の色分け)

- Semantic Scholar Graph API が background / method / result の intent を返す。
- ただし**10^5 論文分を per-paper API で取るのは非現実的**。Semantic Scholar の Datasets(bulk)側に citation contexts / intents が含まれるので、大規模にやるならそちら。
- 代替案: **表示中の部分グラフに対してだけ lazy に取る**。全体は構造だけで描き、ズーム時に intent 色を載せる。

## 6. 描画

- 10^5 ノード + 10^6 エッジ想定 → **WebGL 必須**。候補: deck.gl(レイヤ抽象があり大規模点群に強い)、regl(低レベル・自由度高)、sigma.js(グラフ特化)。
- エッジを全部描くと画面が真っ黒になる。**エッジは加算合成 + 低 alpha** で「濃いところ = 太い流れ」に見せるのが定石。SPC 重みを alpha に載せる。
- **edge bundling** は効果が大きいが計算が重い。まずは alpha 加算で足りるか見る。
- レイアウト計算はブラウザでやらない。**オフラインで前計算 → 座標付きバイナリを配信**(決定的であることの要求とも整合する)。
