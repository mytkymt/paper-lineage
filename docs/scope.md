# Scope — paper-lineage

このドキュメントは「何を作るか / 作らないか」を固定するアンカー。実装が「もう一つの Connected Papers クローン」や「汎用文献管理ツール」に流れないために使う。

## 中心アイデア

論文の引用関係は **時間について厳密に単方向**(先行論文が後発論文を引用することは原則ない)。この制約は他のネットワーク(SNS、Web リンク、共著)にはない。
既存の literature mapping ツールの多くは force-directed / 類似度ベースのレイアウトを主表現にしており、この制約を「フィルタ」としてしか使っていない。

→ **時間軸を第一級の軸に固定し、引用グラフを常に単調な DAG として描く。** 1本の論文を選んだとき、

- **上流(過去)**: その論文が何を引用しているか = どのトレンドの上に乗っているか
- **下流(未来)**: その論文がその後どう引用されたか = どんなトレンドを作ったか

を、同じ画面の上下(または左右)で連続的に読めるようにする。

## 機能スコープ

### F1. 時系列 lineage ビュー(必須・主貢献)

- 1つの seed 論文を選ぶと、上流 N ホップ・下流 N ホップの引用グラフを取得。
- Y 軸(または X 軸)= 出版年。**必ず単調**。同年内の配置のみレイアウトアルゴリズムが決める。
- ノードサイズ = 被引用数(log スケール)。エッジ = 引用。
- 上流/下流の深さ、年レンジ、最低被引用数、分野をコントロールで絞れる。
- ホバーで、その論文が seed 論文とどう繋がっているか(パス)をハイライト。

**このビューが読めなければ他の機能は無意味**、という位置づけ。

### F2. 「流れの太さ」の可視化(必須)

単に点と線を時系列に並べるだけだと、Litmaps の timeline 表示と大差がない。paper-lineage が答えたいのは「**この論文はどれくらいのトレンドを作ったか**」なので:

- 下流側を、年ごとの引用フロー(Sankey / stream graph 的な帯)としても描ける。
- seed の子孫集合が、年を追うごとにどう増え・どこで分岐したかを面積で見せる。
- 分岐した枝が別々のコミュニティに落ちる場合、枝ごとに色を分ける(引用グラフのコミュニティ検出 or embedding クラスタリング)。

### F3. トレンド位置づけの可視化(オプショナル・研究的に一番面白い部分)

ACM / HCI 系の論文は Related Work で「どのトレンド群を踏まえ、自分はどこに立つか」を明示している。これを機械的に取り出せれば、F1 の上流側を「個々の論文」ではなく「**トレンドの束**」として描ける。

想定アプローチ(難易度順):

1. **引用のクラスタリングのみ**(LLM 不要): 上流論文を embedding + クラスタリングし、クラスタにキーワードでラベルを付ける。安いが、著者自身の枠づけとはズレる。
2. **citation intent の利用**: Semantic Scholar Graph API は citation context と intent(background / method / result)を返す。background 引用 = そのトレンドを踏まえている、method 引用 = 技術を借りている、として上流を色分けする。API だけで取れるので費用対効果が高い。**まずここまでを目標にする。**
3. **Related Work セクションの LLM 解析**: OA 全文(arXiv / PMC / OpenAlex の OA link)から Related Work を抽出し、LLM に「この論文が置いているトレンド群と、それぞれに対する自分の立ち位置(拡張 / 対立 / 適用 / 未解決点)」を構造化出力させる。一番欲しい情報だが、全文が取れる論文が限られること・コストが問題。**seed 論文とその周辺だけに限定して適用する。**

F3 は「できたら素晴らしい」枠であり、F1/F2 の完成を遅らせない。

## Non-goals(明示的にやらないこと)

- **文献管理ツールを作らない。** ライブラリ管理・PDF 保管・BibTeX 管理は Paperpile / Zotero の役目。エクスポート連携までに留める。
- **推薦アルゴリズムの精度を主貢献にしない。** 「隠れた重要論文を見つける」は Connected Papers / Research Rabbit の土俵。こちらは**すでに知っている論文の系譜を読む**ためのツール。
- **全分野・全 DB の網羅をしない。** まず HCI(CHI / UIST / CSCW / DIS)で使えることを優先する。
- **スクレイピングをしない。** 公開 API(OpenAlex / Semantic Scholar / Crossref / OpenCitations)の利用規約の範囲内でやる。全文解析も OA のものだけ。
- **ログイン・アカウント機能を初期は作らない。** ローカル / URL 共有で完結させる。

## Success criteria

- 自分の論文(または CHI の代表的な論文)1本を入れると、10秒以内に上流2ホップ・下流2ホップの時系列グラフが出る。
- そのグラフを見て「この論文が乗っている流れ」と「作った流れ」を、他人に口頭で説明できる。
- 同じ論文を Connected Papers / Litmaps で見たときに **読み取れない情報が読み取れる**、と自分で言える(これが言えないなら作る意味がない)。
- API レート制限に当たっても、キャッシュから同じ画面を再現できる。
- URL でグラフの状態を共有できる。

## オープンな問い(実装前に決めたいこと)

- 縦軸か横軸か。年が下に伸びるのが直感的か、左右のほうが引用の「流れ」に見えるか。→ **プロトタイプで両方試す。**
- 下流グラフはすぐ爆発する(被引用1000件の論文が seed だと数万ノード)。デフォルトの間引き基準をどう置くか(被引用数上位 K? 各年上位 K? seed からのパス数?)。
- 「トレンド」の粒度。クラスタ = トレンド、で人間の直感と合うのか。
